# networkmanager-openvpn removed 2026-07-31 — ProtonVPN now runs on WireGuard,
# which NetworkManager speaks natively. The plugin (and openvpn with it) bought
# nothing except an import that could never be unattended: Proton's OpenVPN
# profiles need a separate username and password, a WireGuard config carries its
# own key. The official Proton app stays rejected (GTK).
# libnatpmp removed 2026-07-31 with the port-forwarding service (ulu's call).
# Proton's port forwarding needs a P2P server, and both servers in use refuse
# NAT-PMP; the renewal service was the only consumer. Reviving it means adding
# this back — and enabling qBittorrent's WebUI, which is how the port gets in.
wireguard-tools       # `wg` and `wg-quick`. NetworkManager speaks WireGuard without them, but
                      # the namespace tunnel is built by hand: `wg setconf` loads the keys and
                      # `wg-quick strip` reduces Proton's file to what the kernel accepts.
                      # Missing on the live desktop until 2026-08-06 for exactly that reason —
                      # nothing had ever needed to touch a tunnel outside NM.
dnsmasq               # NOT a DNS server for this machine — it binds one loopback address and
                      # serves nothing else. It exists so the vpnonly group's NAME LOOKUPS go
                      # through the tunnel too: nftables rewrites the group's query from the
                      # systemd-resolved stub to this forwarder, which runs in the group and
                      # asks the resolver inside the tunnel. Without it the traffic was
                      # protected while every tracker name still went to Quad9 over the
                      # ordinary line. A rule pointing straight at the tunnel's resolver was
                      # tried first and cannot work — see LOG.md 2026-08-06.
nftables              # the kernel-side guarantee that qBittorrent can only ever leave through the
                      # tunnel. Explicit BECAUSE it was already installed as someone else's dependency
                      # and therefore one `pacman -Rns` away from vanishing (same lesson as socat)
gobject-introspection-runtime  # DZGUI dependency. It is fetched as an upstream tarball, not a
                      # package, so it cannot declare dependencies at all — and its bundled Python
                      # still needs the SYSTEM typelibs. Without this it dies at startup with
                      # "Typelib file for namespace 'xlib', version '2.0' not found".
                      # This is the dependency LOG.md deferred "to actual install" in the package
                      # rounds; the actual install is where it turned up.
cups                  # printing daemon; printer: Samsung SCX-4300 (USB), print only — no scan stack
