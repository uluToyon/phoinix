# rtkit — PipeWire asks for realtime priority at every start and, without this
# package, is refused it. Measured on this desktop 2026-08-01, in PipeWire's own
# log since the install: "RTKit error: ServiceUnknown / RTKit does not give us
# MaxRealtimePriority, using 1", all three data-loop threads on SCHED_OTHER,
# `ulimit -r` = 0. The consequence is invisible at idle and shows up under a
# loaded game as xruns — two unrelated clients missed the same sampling second,
# which no application bug can do. It is an optional dependency of pipewire, so
# a fresh Arch does not pull it and every machine phoinix built lacked it.
# Chosen over `realtime-privileges` (group + hard rlimits for ALL of ulu's
# processes, needs a re-login): rtkit needs no group, no re-login, and demotes
# runaway realtime threads by design. See LOG.md 2026-08-01.
rtkit
